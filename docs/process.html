dev_tools 전체 프로세스도

여러 개발자가 각자 AI 개발툴을 쓰며 한 프로젝트를 만들 때의 흐름입니다. AI는 빠진 부분(갭)을 찾아 보여 주고, 무엇을 맡을지와 완료 승인은 사람이 결정합니다.

사람이 결정하는 단계 대시보드 dev_tools 서버 AI 개발툴 · 저장소 기본 흐름 예외 · 상시 흐름

단계별 설명

단계주체내용
1사람요구사항·스펙을 작성한다. 갭 탐지의 기준이 된다.
2서버요구사항을 작고 검사 가능한 단위로 나눈다.
3AI 개발툴각 개발자의 세션 활동과 git 변경을 자동으로 보낸다. 개발자가 따로 보고하지 않는다.
4서버요구사항마다 관련 코드를 검색하고 AI가 "구현됨 / 부분 구현 / 없음"을 근거와 함께 판정한다.
5대시보드팀 현황, 갭 후보, 활동 피드, 파일 겹침 경고를 실시간으로 보여 준다.
6사람갭 후보를 확인해 확정하거나 기각하고, 자기가 맡을 작업을 정한다.
7대시보드맡을 갭에 claim을 등록한다.
8서버담당자와 상태를 한 번에 기록한다. 한 갭은 한 사람만 맡을 수 있고, 활동이 끊기면 만료된다.
9AI 개발툴개발자가 자기 AI 개발툴로 구현한다. 작업 공간은 개발자별로 분리한다.
10서버테스트 결과와 리뷰 상태로 완료를 검증한다.
11대시보드완료를 표시하고 갭 목록을 갱신한다.
12사람완료를 승인하고 다음 갭을 고른다. 6단계로 돌아가 반복한다.

예외 흐름

Claim 만료

맡은 뒤 일정 시간 활동이 없으면 claim이 풀리고 갭 목록으로 돌아간다. 방치된 작업이 다른 사람을 막지 않게 한다.

오탐 기각

AI가 구현된 부분을 갭으로 잘못 판정할 수 있다. 사람이 6단계에서 기각하면 목록에서 빠지고, 기각 기록은 판정 정확도를 재는 데 쓴다.

작업 겹침 경고

서로 다른 개발자의 작업이 같은 파일에 겹치면 커밋 전에 대시보드에 경고가 뜬다.

완료 승인 뒤: 출시와 전달

모든 빈 곳이 채워지고 승인된 다음의 다섯 단계입니다. 출시 승인을 뺀 나머지는 실행기가 자동으로 수행하고, 실행기는 담당자의 컴퓨터나 CI에서 돕니다.

단계주체내용
13실행기이번 버전의 작업을 모두 합친 상태에서 전체 테스트를 돌린다. 실패하면 관련 요구사항이 빈 곳으로 돌아간다.
14실행기출시 방법서대로 결과물을 만들고 고객이 원하는 형식으로 가공한다. 확인값을 계산한다.
15사람책임자가 출시를 승인한다. 실행기는 승인을 기다리며 멈춰 있다.
16실행기클라우드 저장소에 올리고 메일로 알리거나, 고객 서버에 SSH로 설치하고 새 버전으로 전환한다.
17실행기 사람운영 확인을 돌린다. 눈으로 봐야 하는 것은 담당자가 본다. 실패하면 자동으로 이전 버전으로 되돌린다.

dev_tools 서버가 하는 일

진행을 실시간으로 보여 주고, 승인을 받고, 기록을 남긴다. 직접 빌드하거나 고객 서버에 접속하지 않는다.

자동으로 못 할 때

고객이 자동 접속을 허락하지 않으면 같은 출시 방법서를 점검표로 삼아 담당자가 손으로 수행한다.

전달한 뒤

고객의 의견과 발견된 문제는 새 요구사항이 되어 빈 곳 목록에 들어가고, 6단계부터 다시 돈다.
